# Песочница и безопасность

Безопасность игроков и изоляция модификаций — ключевой приоритет архитектуры Velvetics-Core. Среда исполнения Lua изолирована с помощью строгих программных барьеров.

---

## Профиль песочницы: `Preset_SoftSandbox`

Виртуальная машина MoonSharp каждого мода инициализируется с пресетом мягкой песочницы (`CoreModules.Preset_SoftSandbox`), который включает в себя только безопасные алгоритмические библиотеки:

### Разрешенные стандартные библиотеки Lua:
- **`Basic`** — базовые функции: `assert`, `error`, `ipairs`, `pairs`, `next`, `pcall`, `xpcall`, `select`, `tonumber`, `tostring`, `type`, `unpack`.
- **`Table`** — операции над таблицами: `table.insert`, `table.remove`, `table.sort`, `table.concat`.
- **`String`** — строковые операции: `string.format`, `string.sub`, `string.find`, `string.gsub`, `string.match`, `string.len`.
- **`Math`** — математические функции: `math.abs`, `math.sin`, `math.cos`, `math.floor`, `math.ceil`, `math.random`, `math.sqrt`.
- **`Bit32`** — побитовые логические операции: `bit32.band`, `bit32.bor`, `bit32.bxor`, `bit32.lshift`, `bit32.rshift`.

## Запрещенные опасные интерфейсы

Следующие стандартные модули Lua полностью **отключены** в целях предотвращения выполнения вредоносного кода:

| Запрещенный модуль | Причина блокировки |
| :--- | :--- |
| **`os`** (`os.execute`, `os.remove`, `os.getenv`) | Запрещает выполнение произвольных системных команд, запуск сторонних исполняемых файлов (`.exe`, `.bat`) и доступ к переменным окружения ОС игрока. |
| **`io`** (`io.open`, `io.read`, `io.write`) | Запрещает прямой неконтролируемый доступ к файловой системе компьютера вне песочницы мода. |
| **`debug`** (`debug.getinfo`, `debug.sethook`) | Запрещает низкоуровневые манипуляции со стеком вызовов и обход барьеров безопасности. |
| **`package`** (`package.loadlib`) | Запрещает загрузку произвольных нативных библиотек (`.dll`, `.so`). |

## Защита от выхода за пределы папки (Path Traversal)

Для всех операций чтения файлов (`Mod.load_sprite`, `Mod.load_texture`, `Mod.read_text`, `Mod.asset_exists`, а также встроенного `require`) реализован жесткий валидатор путей.

При каждой попытке доступа путь нормализуется в абсолютный канонический вид через `Path.GetFullPath`. Если результирующий путь не начинается с базового пути папки текущего мода, операция немедленно блокируется с записью в лог:

```text
Security violation: attempt to access path outside mod directory: ../../../Windows/System32
```

Это гарантирует, что мод не может прочитать личные данные пользователя или испортить системные файлы.

## Изоляция состояния между модами

Каждый активный мод работает в собственном независимом экземпляре `Script`. 
- Глобальные переменные, объявленные в файле `main.lua` одного мода, **не видны** и **не могут конфликтовать** с переменными другого мода.
- Взаимодействие между независимыми модами осуществляется исключительно через безопасную шину [`Events`](api/events.md).
