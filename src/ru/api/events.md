# Модуль Events (Шина событий)

Таблица `Events` (или `events`) предоставляет механизм публикации и подписки (Publish/Subscribe) для организации связи между различными модами и игровыми подсистемами.

---

## Методы

### `Events.subscribe(eventName, callback)`
Регистрирует функцию-слушатель для события с указанным строковым именем.

- **Параметры:**
  - `eventName` (`string`): имя события.
  - `callback` (`function(data)`): функция, вызываемая при возникновении события.
- **Псевдоним:** `Events.Subscribe(...)`.

---

### `Events.unsubscribe(eventName, callback)`
Удаляет ранее зарегистрированную функцию из списка слушателей.

- **Параметры:**
  - `eventName` (`string`): имя события.
  - `callback` (`function`): ссылка на функцию-слушатель.
- **Псевдоним:** `Events.Unsubscribe(...)`.

---

### `Events.fire(eventName, data)`
Генерирует событие и немедленно оповещает всех зарегистрированных слушателей во всех активных модах.

- **Параметры:**
  - `eventName` (`string`): имя события.
  - `data` (`any`): полезная нагрузка (число, строка, таблица или объект).
- **Псевдоним:** `Events.Fire(...)`.

---

## Пример межмодового взаимодействия

### Мод А: "ExplosionPack"
```lua
function TriggerBigBoom(pos_x, pos_y)
    Log("Взрыв в точке X=" .. pos_x .. " Y=" .. pos_y)
    Events.fire("on_explosion", { x = pos_x, y = pos_y, power = 150 })
end
```

### Мод Б: "CameraEffects"
```lua
function OnInit()
    Events.subscribe("on_explosion", function(boom)
        Log("Камера зафиксировала взрыв мощности " .. boom.power .. "! Запуск тряски...")
        -- Логика тряски камеры
    end)
end
```

---

## Безопасность и очистка памяти

При отключении или перезагрузке модификации системный класс `ModEventBus` автоматически удаляет все подписки, привязанные к виртуальной машине выгружаемого мода. Это гарантирует отсутствие "висячих" ссылок и вызовов удаленного кода.
